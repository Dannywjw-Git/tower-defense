## 2. 技术栈与交付形态

### 2.1 引擎版本：Phaser **3.90.0**（非 4.x）

| 依据 | 3.90.0 | 4.2.1 |
|---|---|---|
| 版本迭代数 | **60 个**（2025-05-23 收尾） | 仅 **4 个**（2026-07-09） |
| `min` 体积 | **1168 KB** | 1344 KB |
| 生态（教程/插件/示例） | 绝大多数为 v3 | 少 |
| 实现可靠性 | 高 | 无法保证（API 有变动） |

v4 宣称的"体积减 40%"指的是**开发版**；`min` 版实测更大。目标是"送朋友玩"，**稳定 > 新**。

### 2.2 dist 选择

**`phaser-arcade-physics.min.js`（1061 KB）**——比完整版省 108 KB。
塔防只需要"圆形距离判定 + AABB"，Arcade Physics 足够；去掉的是 Matter.js 刚体物理（用不上）。

### 2.3 四项工程决定

| 项 | 决定 | 理由 |
|---|---|---|
| **引入方式** | **本地文件**，不用公共 CDN | 国内公共 CDN 可用性不稳定（参见 `home-hub-ops-pitfalls`：GitHub 代理/gh.ddlc.top/hf-mirror 等），朋友网络更不可控。引擎文件必须自持 |
| **模块化** | **原生 ES modules**（`<script type="module">`） | 浏览器原生能力，`import`/`export` 直接可用，**无需任何构建步骤** |
| **托管** | 纯静态，**无后端** | 分数存 `localStorage`，服务器只发文件 |
| **构建工具** | **无** | 无 `npm install`、无 `dist/` 产物。部署 = 上传文件 |

> `file://` 下 ES modules 无法工作，因此**必须通过 HTTP 访问**（与约束 2 一致）。

### 2.5 响应式策略

- Phaser `Scale Manager`：**`Scale.RESIZE`**（**不是** `FIT`）——逻辑坐标 = CSS 像素，HUD 文字不随地图缩放
- 地图**固定 8 列 × 5 行**；格子 = `min(可用宽 ÷ 8, 可用高 ÷ 5)`
- **不向上 clamp**：强制放大到 44 px 会让总宽溢出窄屏，换不来可点性。44 px 只作**报警线**
- HUD 两套排布：**竖屏占上下固定区；横屏改左右浮层**（横屏的病根是纵向不足，Phase 0 实测）
- Phase 0 实测数据与推导见 §6.1

### 2.6 命名与路径规则：目录 ASCII，内容中文

| 层 | 用中文？ | 说明 |
|---|---|---|
| 磁盘目录 / 文件名 | ❌ **ASCII** | `tower-defense/`，不是 `塔防游戏/` |
| URL 路径 | ❌ **ASCII** | 同上——目录名会直接进链接 |
| 页面标题 / UI 文案 / README / spec 正文 | ✅ **中文** | 显示名仍是「塔防游戏」 |

**为什么目录必须 ASCII**——不是洁癖，是三条具体代价：

1. **目录名会进 URL**。发微信给朋友的链接会变成 `.../%E5%A1%94%E9%98%B2%E6%B8%B8%E6%88%8F/`——一长串转义，聊天客户端可能截断，朋友手输不可能。
2. **本项目要写 PowerShell 辅助脚本**（本地预览服务器、部署脚本）。`home-hub-ops-pitfalls` 已记录的坑包括：`.ps1` 中文乱码（全角引号吞字符，需 UTF-8 with BOM）、`os.remove` 中文路径、`python -c` 中文、`PYTHONUTF8`、GBK 编码。
3. **部署 / 隧道工具对非 ASCII 路径的编码处理不一致**（Cloudflare Pages、OSS、Caddy 各不相同）。

> `家庭智能中枢` 用中文目录名没出问题，是因为它**不暴露为 URL、不对外分发**——差别在此。

### 2.7 部署：GitHub Pages（v1 方案）

**决定**：用 GitHub Pages 托管。朋友在国内、可正常访问（用户确认），无需域名、无需备案。

| 项 | 值 |
|---|---|
| 费用 | **0** |
| 域名 | 默认 `<user>.github.io/<repo>/`（无自定义域名） |
| 备案 | 不需要 |
| **依赖你家机器** | **否** ← 关键：朋友任何时候点开都能玩，与你家设备开关机无关 |
| 部署方式 | `git push` → Pages 自动构建 |
| 上线 URL 形态 | `https://<user>.github.io/<repo>/` |

#### 三条必须遵守的技术约束（否则必踩坑）

1. **资源引用一律用相对路径**。项目仓库的 URL 带子路径（`/<repo>/`），用绝对路径会 404：
   - ✅ `./assets/x.png` 或 `assets/x.png`
   - ❌ `/assets/x.png`
   - ES modules 的 import 同理：`import Tower from './entities/Tower.js'`

2. **仓库根放一个空 `.nojekyll` 文件**。GitHub Pages 默认跑 Jekyll，会忽略下划线开头的文件 / 目录并拖慢构建；该文件用于关闭它。

3. **`vendor/phaser.min.js`（1061 KB）必须进仓库**。选了"本地引入、不用 CDN"就要付出这个代价——换来的是不依赖任何第三方 CDN 的可用性。

#### 迁移预案

整个项目**无后端、无构建**，所以若实测发现访问不稳，迁到阿里云 OSS / 腾讯云 COS **只是上传同一批文件，零代码改动**。这是纯静态架构换来的保险。

## 3. 架构与数据流

### 3.1 场景生命周期

```
BootScene ──▶ MenuScene ──▶ LevelSelectScene ──▶ GameScene ──┬──▶ ResultScene ──▶ MenuScene
（加载+进度条）  （标题）      （选关）            核心玩法      │    （胜/败结算）
                                                          └──▶ HudScene（并行）
```

`HudScene` 用 `scene.launch()` **并行**运行（不是 `start()`，后者会顶掉 `GameScene`），实现"地图缩放、HUD 不缩放"。

### 3.2 核心循环（每帧顺序固定）

**delta-time 驱动，绝不假设固定 60 帧步长**（手机帧率会掉）：

1. `WaveManager` 判断是否该刷下一波 / 下一只
2. 敌人沿路径点插值前进，推进「当前段索引 + 段内 t」
3. 塔的索敌（**仅当冷却就绪才计算**）
4. 伤害结算（含**已缓存**的协同加成——协同在建塔/卖塔时重算，见 §5.1）
5. 经济结算（击杀奖励 / 漏怪扣命）
6. 胜负判定

**对象池**：敌人与弹道使用 Phaser `Group` 的 `get()` / `kill()` 复用，**不 new/destroy 对象**——否则一波 30 只怪会触发 GC 卡顿。

### 3.3 伤害结算：**锁定即扣血**（方案 B）

塔锁定目标后**立即结算伤害**，弹道只是视觉动画。

**理由**：避免"目标中途死亡 / 走出射程"的一整类边界情况；手机性能更好。塔防的爽感来自"塔打死了怪"，不来自"子弹飞到"。

### 3.4 实体模型

| 实体 | 持有 | **不**持有 |
|---|---|---|
| `Enemy` | 位置、HP、速度、路径进度、赏金、减速状态 | 全局金币/生命 |
| `Tower` | 格坐标、类型、等级、冷却、索敌策略、射程 | 敌人列表（查询场景） |
| `Projectile` | 起点/终点、飞行 t、伤害 | 目标引用（方案 B 不需要） |

### 3.5 状态分三层

| 层 | 位置 | 内容 |
|---|---|---|
| **局内状态** | `GameState` 对象统一持有 | 金币 / 生命 / 波次 / 已建塔列表 |
| **实体状态** | 各实体自持 | HP、冷却… |
| **UI 状态** | `HudScene` 持有 | 当前选中塔型、是否处于建造模式 |

**集中 `GameState` 的理由**：存档、重开、胜负判定只需读写一个对象，无需遍历场景实体凑数。

### 3.6 数据驱动（数值与代码分离）

所有数值放 `src/data/`，**代码内不写魔法数字**。调平衡只改数据文件，不碰逻辑。

### 3.7 存档结构（`localStorage`）

```js
{
  version: 1,                     // 格式版本 —— 不可省略，否则未来改格式会静默损坏旧存档
  best:    { score, wave, levelId },
  cleared: ["level-01"],
  progress: { levelId, wave, gold, lives, towers: [{ x, y, type, level }] }
}
```

### 3.8 错误处理与中断处理（五条必须兜住）

| 风险 | 处理 |
|---|---|
| 素材加载失败 | `BootScene` 监听 `loaderror` → 用矩形占位符替代，**不白屏** |
| `localStorage` 不可用（隐私模式 / 配额满） | `try/catch` 包裹 → 降级为"本局不存档"，不影响游玩 |
| WebGL 不可用 | 渲染器设 `AUTO` → 自动回落 Canvas |
| **切后台 / 来电后返回** | 🔴 监听 `visibilitychange` → **立即自动暂停**。否则 `delta` 暴涨到数秒，一波怪瞬间涌出直接打穿玩家。**每一局都会发生，不是边缘情况** |
| **双指缩放 / 双击缩放误触** | viewport 设 `user-scalable=no`，并禁用双击缩放 |

## 4. 内容设计

### 4.1 塔：6 种 × 3 级

| 塔 | 造价 | 定位 | 克制对象 |
|---|---|---|---|
| **箭塔** | 50 | 单体、快速、中射程 | 基线，性价比 |
| **炮塔** | 80 | 溅射（半径 40）、慢、近射程 | 成群小怪 |
| **冰塔** | 60 | 减速 40%/2s、低伤 | 快速怪 |
| **电塔** | 100 | 连锁闪电（跳 3 目标，无弹道） | 中密度群 |
| **毒塔** | 70 | 持续伤害、**无视护甲** | 坦克 |
| **狙击塔** | 120 | 超远射程、极慢、超高单伤 | 精英 |

> **数值粒度说明**：上表只定**造价与定位**（相对关系）。各塔伤害/射程/攻速的**具体数值**及 18 条升级数据，在阶段③ 实施计划中逐条落定——它们的正确取值只能由实测决定，现在写死等于制造返工。

**Lv3 必须有"质变"而非纯数值放大**，否则升级只是无聊的乘法：

| 塔 | Lv3 质变 |
|---|---|
| 箭塔 | 穿透 2 个目标 |
| 炮塔 | 溅射半径 +50% |
| 冰塔 | 触发定身 1s |
| 电塔 | 连锁目标 +1 |
| 毒塔 | 毒伤翻倍 |
| 狙击塔 | 破甲（无视护甲） |

> ⚠️ **平衡工作量**：6 种 × 3 级 = 18 条升级数据 + 15 组协同关系。这是用户明确选择的规模，实测期必然反复调整。

### 4.2 敌人：3 种 + 1 精英变体

| 类型 | HP | 护甲 | 速度 | 赏金 | 漏怪扣命 | 逼玩家用什么 |
|---|---|---|---|---|---|---|
| 普通 | 60 | 0 | 中 | 8 | 1 | 基线 |
| 快速 | 35 | 0 | **1.8×** | 6 | 1 | **减速** |
| 坦克 | 220 | **8** | **0.6×** | 15 | 1 | **高伤 / 无视护甲** |
| 精英（每关末） | 900 | **12** | 中 | 40 | **3** | 全部手段 |

**护甲机制**：实际伤害 = `max(1, 伤害 − 护甲)`（保底 1，避免完全免疫）。

> **为什么必须有护甲**：它是**毒塔（无视护甲）**与**狙击塔 Lv3（破甲）**的存在理由。没有护甲，这两张牌的定位会落空——这是本 spec 首轮自查发现的内部矛盾。

**HP 随波次线性增长**：`HP = base × (1 + 0.18 × (波数 − 1))`

> **明确不用指数增长**——指数曲线会让第 10 波突然无解，是数值设计偷懒。

精英 = 复用普通怪机制 + 放大数值 + 换外观，**不引入新机制**（成本主要在美术）。

### 4.3 关卡：架构支持 N 张，v1 做 2 张

**地图规格（全部关卡统一）：8 列 × 5 行 = 40 格**

| 地图 | 用途 | 波数 |
|---|---|---|
| **地图 1「教学」** | 直线为主的简单路径，教放塔/升级/看波次 | 8 |
| **地图 2「转弯」** | 有回环，塔位价值分层，需要取舍 | 12 |

> **40 格为什么够**：路径占约 12 格，剩余 **25–28 个可建塔位**。地图用**格子坐标**而非像素坐标，因此同一份数据在竖屏、横屏、电脑上渲染一致——见 §6.1。

**扩展契约**：新增一张地图 = 新建一个数据文件 + 在 `levels/index.js` 加一行。**不改任何逻辑代码**。关卡总数不硬编码，`LevelSelectScene` 从注册表动态生成按钮。

### 4.4 经济基线

| 项 | 值 | 说明 |
|---|---|---|
| 起始金币 | **120**（教学关） | 够 2 箭塔，或 1 箭 + 1 冰。**进阶关按难度调整**——地图 2 用 **150** |
| 起始生命 | **20** | 两关一致 |
| 每波清空奖励 | **20 + 波数 × 5** | 递增，防后期经济崩 |
| 击杀赏金 | 见 §4.2 | |
| 卖塔退款 | **累计投入的 70%**（含升级费） | |

> ⚠️ 初版此处只写了"起始金币 120"、未区分关卡，而地图 2 实际用 150。
> 实现与文档的偏差已在此修正（Phase 8 代码审查发现）。

> 以上为**起点而非承诺**。塔防平衡只能靠实测，这也是 §3.6 数据驱动存在的意义。

### 4.5 操作与辅助

| 功能 | 做 | 说明 |
|---|---|---|
| 暂停 | ✅ | 手机上被打断是常态 |
| 1× / 2× 加速 | ✅ | 实现只是改 delta 倍率，成本极低、体验极高 |
| 音效 | ✅ | ⚠️ 浏览器音频策略：**必须用户首次点击后才能播放**，在开始按钮里解锁 |
| 塔信息面板 | ✅ | 点击已建塔显示伤害/射程/升级价/协同 |

## 5. 创新机制（差异化设计）

### 5.1 相邻协同阵型

**邻域取 4 格（上下左右），不含对角**——手机小屏上对角线会交叠成一团，看不清协同关系。

| 情形 | 效果 |
|---|---|
| 每有一个**不同类型**的相邻塔 | 本塔 **+5% 伤害**（最多 4 层 = **+20%**） |
| **同类**相邻 | **无加成** |
| 特例组合 | 覆盖通用规则，**取更高者，不叠加** |

**同类不给加成是硬规则**：否则"堆一堆箭塔"成为最优解，6 种塔退化成 1 种。**只有混搭才有收益**，6 种的选择才成立。

#### 特例组合（只做 3 组，保证记得住）

| 组合 | **受益方** | 效果 | 逻辑 |
|---|---|---|---|
| **冰 + 箭** | **箭塔**（单向） | 攻速 **+20%** | 被冻住的目标就是靶子 |
| **炮 + 毒** | **炮塔**（单向） | 溅射半径 **+25%** | 毒雾随冲击波扩散 |
| **电 + 冰** | **电塔**（单向） | 连锁 **+1 目标** | 减速场让电流更易传导 |

**特例是单向的**：只加成表中指名的那一方；另一方不获得该特例，但它仍吃到通用的"异类相邻 +5% 伤害"。

**计算时机**：协同加成在**建塔 / 卖塔 / 升级时重算**并**缓存**到塔的属性上——**不在每帧计算**（每帧遍历邻域是纯浪费）。

#### 视觉呈现（决定这个机制能否被理解）

- **建造/选中时**：相邻格高亮，显示"若建在此处 → 协同 +X%"
- **已生效**：相邻塔之间画**淡连线**（4 邻域只有直线，视觉干净）
- **信息面板**：明确列出"协同：箭塔 +10%（2 个异类邻居）"

> **没有视觉提示的协同等于不存在**——玩家不读规则，只看画面。

### 5.2 点击参与

| 项 | 值 | 理由 |
|---|---|---|
| 伤害 | 敌人**最大 HP 的 2%**，单次**上限 20** | 百分比对普通怪与精英都有意义；上限防止精英被手速秒 |
| 冷却 | **0.25 s** | 防连点 |
| 赏金 | **不额外给** | 击杀赏金照常（谁杀都给）。避免"点就赚钱"的刷钱漏洞 |

**价值定位**：不是赚钱手段，而是**补刀防漏怪**——快跑掉的怪被你点死，保住 1 点生命。把"等波次的空转"变成"盯漏网的紧张感"。

#### 输入模式（双端统一 `pointerdown`）

| 当前模式 | 点敌人 | 点空地 | 点已有的塔 |
|---|---|---|---|
| **非建造模式** | 攻击 | 无操作 | 打开信息面板 |
| **建造模式** | 放置塔 | 放置塔 | **禁止覆盖** → 退出模式 + 打开该塔面板 |

> **"禁止覆盖已有塔"是硬规则**——手机上误触把 50 金币的塔盖掉不可接受。

**反馈**：命中 → 小爆点 + 伤害飘字 + 轻微音效。**没有反馈的点击等于没做。**

### 5.3 对已有设计的影响

| 影响面 | 变化 |
|---|---|
| 地图设计 | 需预留"协同友好"的塔位簇（相邻可建格），不能只有孤立点 |
| UI | 建造模式成为明确状态；信息面板加"协同"行与「出售」按钮 |
| 存档 | 不变——协同由**位置推导**，无需存储 |
| 纯逻辑模块 | 新增 `Adjacency`（协同计算），纯函数，可测 |
| 测试 | 协同叠加是否封顶、特例是否覆盖通用、同类是否真的不加成 |

## 6. UI 与引导

### 6.1 竖屏原生可玩（**不再要求横屏**）

**背景**：原设计用「请横屏游玩」遮罩。阶段② 审查推翻它——**iOS 微信内置浏览器无法可靠强制横屏**（`screen.orientation.lock()` 需全屏模式且可能被拦截；业界 fallback 的 CSS 整体旋转会让触摸坐标错乱，对"点格子"的塔防是灾难）。而"朋友在微信里点开"恰恰是最可能的入口。

**解法不靠旋转，靠放大格子。**竖屏玩不了横屏地图的唯一原因是**格子太小、手指点不中**：

| 地图规格 | 竖屏（375 px 宽）每格 | 手指标准 ≥44 px |
|---|---|---|
| 16×9（常规塔防） | **23 px** | ❌ |
| 10×6 | 37 px | 🟡 |
| **8×5** ← **采用** | **47 px** | ✅ |

**地图固定 8 列 × 5 行 = 40 格**；路径占约 12 格 → **可建塔位约 25–28 个**。

#### 渲染模式：`Scale.RESIZE` + 动态布局（**不是** `FIT`）

**为什么不用 `FIT` + 固定逻辑分辨率**：竖屏下整个画面会缩到 0.39 倍，HUD 文字变成 4.7 px，**根本看不清**。

采用 `Scale.RESIZE`——画布匹配实际窗口，**逻辑坐标 = CSS 像素**，HUD 文字始终清晰。

**格子尺寸算法（Phase 0 实测校准后）**：

```js
const landscape = W > H
const availW = landscape ? W - sideW * 2 - 16 : W - 8
const availH = landscape ? H - 32 : H - HUD_H - 46

cell = Math.min(availW / 8, availH / 5)   // 不向上 clamp！
```

> ⚠️ **不要向上 clamp 到 44 px**。初版写的是 `Math.max(cell, 44)`，Phase 0 实测证明它是错的：强制放大到 44 px 会让格子总宽**溢出窄屏**（360 px 屏上 8×44 = 352 > 344 可用宽），而可点性并不会因此改善。44 px 只作**报警线**，用于着色提示。

**横屏时 HUD 改左右浮层**——Phase 0 抓出的反直觉问题：横屏的病根是**纵向空间不足**，不是宽度。812×375 下若 HUD 占上下 194 px，只剩 181 px ÷ 5 行 = **36 px，不合格**；改为左右浮层后纵向全部让给地图，**cell 升到 54.8 px（+51%）**。

#### 实测数据（Phase 0 · 无头浏览器，6 视口全 0 错误）

| 视口 | HUD 模式 | cell | 判定 |
|---|---|---|---|
| 375×812（iPhone） | 竖屏上下 | **45.9 px** | ✅ |
| 360×640（安卓通用） | 竖屏上下 | **44.0 px** | ✅ 压线 |
| 320×568（老设备） | 竖屏上下 | **39.0 px** | ⚠️ 已接受降级 |
| 430×932（大屏安卓） | 竖屏上下 | **52.8 px** | ✅ |
| 812×375（手机横屏） | 左右浮层 | **54.8 px** | ✅ |
| 1440×900（电脑） | 左右浮层 | **128.0 px** | ✅ |

**四项架构假设已验证**：`Scale.RESIZE` 生效（canvas 恒等于 window 尺寸）· WebGL 可用 · 触摸坐标准确（点中心命中中间格）· 无 JS 错误。

> **320 px 老设备接受降级**：iPhone SE 一代一类设备占比极低，39 px 仍可点击；强行保证 44 px 就得砍到 7 列，为极少数设备牺牲所有设备的布局空间，不划算。

> **仍未验证**：以上均为桌面无头浏览器数据。**iOS 微信 / 安卓 X5 内核的真实行为必须由真机确认**——这是 Phase 0 的原始目的，尚未完成。

**一套地图数据、一套代码适配全部朝向**，无需旋转、无需两套地图坐标系。

#### 代价（已知并接受）

1. **地图变"粗"**——40 格少于常规塔防，路径蜿蜒自由度下降，塔位策略空间略小
2. **HUD 需两套排布**（横屏叠加 / 竖屏上下分离），多写一层布局逻辑
3. **未验证项**：8×5 是否撑得住 12 波。若不够，放宽到 **9×5（45 格，竖屏每格 41 px，仍接近标准）**——这是预留的降级余地

#### 收益

**微信里点开即玩**，不分 iOS / Android、不管旋转锁状态。这正是「给别人玩」的核心指标。

### 6.2 HUD 布局（`HudScene`，真实像素，两套排布）

因采用 `Scale.RESIZE`，HUD 坐标即 CSS 像素，**文字不随地图缩放**。

**横屏 / 电脑**（HUD 为**左右浮层**，纵向空间全部让给地图）：

```
┌───────┬────────────────────────────┬───────┐
│ 💰120 │                            │ [箭]  │
│ ❤️20  │                            │ [炮]  │
│ 波 3/8│    （地图 8×5 格，居中）      │ [冰]  │
│ [⏸]   │                            │ [电]  │
│ [1×/2×]│                           │ [毒]  │
│       │                            │ [狙]  │
│       │                            │ [取消]│
└───────┴────────────────────────────┴───────┘
 sideW≈22%        地图区域             sideW≈22%
```

> **为什么横屏必须用左右浮层**：Phase 0 实测发现横屏的病根是**纵向不足**，不是宽度。812×375 下 HUD 若占上下 194 px，只剩 181 px ÷ 5 行 = **36 px 不合格**；改左右浮层后纵向全给地图，**cell 升到 54.8 px**。

**手机竖屏**（HUD 占用上下留白，不与地图争空间）：

```
┌──────────────┐
│ 💰120  ❤️20   │  ← 顶部状态条（60 px）
│ 波 3/8 [⏸][2×]│
├──────────────┤
│              │
│   （地图）     │  ← 8×5 格，约 375×234
│              │
│              │  ← 留白（信息面板出现在此）
├──────────────┤
│ [箭][炮][冰]  │  ← 建造栏 3×2
│ [电][毒][狙]  │     每格约 110×70
│      [取消]   │
└──────────────┘
```

- 建造栏**纯图标**（无文字标签）；横屏下 6 个各占约 120 px，竖屏下 3×2
- 长按才弹文字说明——**手机无 hover**
- **朝向切换时 HUD 重排而非重建**（监听 `resize` / `orientationchange`，调用同一个 `layout()`）

### 6.3 双端输入映射（全部走 `pointerdown`，一套代码吃两端）

| 操作 | 电脑 | 手机 |
|---|---|---|
| 选塔型 | 点击底部图标 | 点击底部图标 |
| 放塔 | 点击绿色格 | 点击绿色格 |
| 看塔 | 点击已有的塔 | 点击已有的塔 |
| 升级 / 出售 | 面板按钮 | 面板按钮，**出售需二次确认** |
| 补刀 | 左键点敌人 | 点敌人 |
| 取消建造 | `Esc` / 右键 / 再点图标 | 「取消」按钮 / 再点图标 |

> **铁律：手机上没有 hover**——所有信息必须在**点击后**出现。禁止设计"鼠标悬停查看"。此约束渗透到每一个 UI 组件。

### 6.4 建造交互流（完整状态机）

```
点击塔图标
  ├─ 金币不足 → 图标置灰，点击弹"金币不足"，不入模式
  └─ 进入建造模式
       ├─ 可建格：绿色高亮
       ├─ 不可建格：变暗
       ├─ 相邻格：显示协同预览「若建此处 → 箭塔 +10%」
       └─ 点击
            ├─ 空格         → 扣钱 → 建塔 → 音效 → **退出模式**
            ├─ 已有塔       → **禁止覆盖** → 退出模式 + 打开该塔面板
            ├─ 不可建格     → 提示 + **留在模式内**（不打断）
            └─ 建造栏/取消  → 退出模式
```

### 6.5 新手引导：事件驱动

| 手段 | 做法 |
|---|---|
| **首关三步提示** | 中央文字：①"点下方图标选塔" ②"点绿色格子放塔" ③"点敌人可以补刀"。**每条在玩家完成对应动作后消失**（事件驱动，非定时器） |
| **首波准备时间** | 第一关给 **15 秒**再开怪，让玩家放得下第一座塔 |
| **常驻可查** | 塔面板写明伤害/射程/协同；波次预告显示下一波敌人类型 |

**不做**：分步高亮遮罩、强制引导流程、对话气泡——成本高且烦人。

> **为什么事件驱动关键**：定时器式引导在快玩家身上会卡住（"我都放完三座塔了还在教我怎么放塔"）。

### 6.6 素材落地：占位优先，避免阻塞

素材需人工挑选下载，存在阻塞风险，因此做两层隔离：

```
assets/assets.js   ← 唯一素材清单（key → 路径 + 尺寸）
```

| 阶段 | 用什么 | 目的 |
|---|---|---|
| **先** | 代码绘制的**纯色矩形/圆形占位** | 让逻辑、平衡、UI 全部跑通，**不被素材阻塞** |
| **后** | 按清单换成 Kenney 素材 | 只改路径，**逻辑代码零改动** |

**游戏内致谢**：Kenney 素材为 CC0（无需署名），但标题页仍放一行 `Art & SFX: Kenney.nl`——基本礼貌，也给人专业感。

## 7. 测试与验收标准

### 7.1 自动化测试（纯逻辑）

按 ponytail 口径（**不装 TDD 技能**）：把**纯逻辑**写成不依赖 Phaser 的模块——

| 模块 | 职责 |
|---|---|
| `Economy` | 金币收支、卖塔退款（退款 70%、不允许负金币） |
| `Targeting` | 选哪个敌人（最近 / 最先 / 最强） |
| `WaveManager` | 波次推进、HP 线性增长公式 |
| `PathMath` | 路径插值 |
| `Adjacency` | 协同计算（叠加封顶 4 层、特例覆盖通用、同类不加成） |

这些是纯函数 / 纯类，用 `tests/check.html` 跑 assert 即可验证。**渲染与手感不做自动化测试**，靠手动验收。

**额外收益**：将来若换引擎（回原生 Canvas 或上 v4），这层逻辑可整块搬走。

### 7.2 性能与兼容验收线（**阶段⑤ 必须真机实测取证**）

| 项 | 验收标准 | 测法 |
|---|---|---|
| **帧率** | **中端安卓机 + 微信内置浏览器**，满波（≈30 怪 + 15 塔 + 特效）**≥ 30 fps** | 真机，游戏内显示帧率 |
| **竖屏可玩** | 手机竖屏下格子 **≥44 CSS px**，能准确点中目标格 | 真机手指实测 |
| **首屏** | 移动网络下 **≤ 5 秒**出现可交互画面 | 真机 + 浏览器网络面板 |
| **iOS 微信** | 能打开、能玩（**不要求横屏**） | 真机实测 |
| **切后台恢复** | 切走 30 秒再回来，**已自动暂停**且状态无损 | 真机实测 |

> **这一节是阶段② 审查要求补上的**：原 spec 没有任何可验证的性能数字，导致阶段⑤「验证」阶段无据可依——`verification-before-completion` 要求"先有证据才能声明完成"，而"没有验收标准"等于永远无法取证。

## 8. 明确砍掉的功能（YAGNI）

| 砍掉 | 理由 |
|---|---|
| 飞行敌人 | 需要"对空/对地"双套索敌，机制成本远超收益 |
| 主动技能 / 英雄单位 | 王国保卫战那套，是另一个量级的项目 |
| 多路径分支 / 敌人分叉 | 寻路复杂度陡增 |
| 无尽模式 | 需要无限难度曲线设计 |
| 成就 / 每日挑战 | 留存功能，非"打开就能玩"的必要条件 |
| 排行榜 / 云存档 | 约束 5：无后端 |
| 地形亲和（创新候选④） | 与"相邻协同"在布局深度上重叠，同时上会让设计变浑 |
| 塔的经验成长（候选⑤） | 会改写经济模型，属于重做而非"一点点差异" |
